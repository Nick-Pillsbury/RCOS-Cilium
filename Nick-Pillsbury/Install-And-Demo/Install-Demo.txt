Starwars demo and install, https://docs.cilium.io/en/stable/gettingstarted/demo/

Notes:
Step 1: Install Kubernetes Deployment File.
    kubectl create -f https://raw.githubusercontent.com/cilium/cilium/1.17.0/examples/minikube/http-sw-app.yaml
        We have 2 clients and 1 server. One client is supoosed to be deined and the other accepted.

Step 2: See Pods and endpoints
    kubectl get pods,svc
        shows the pods, status, and Clusters
    kubectl -n kube-system get pods -l k8s-app=cilium
        gets the local cilium agent
    kubectl -n kube-system exec cilium-5ngzd -- cilium-dbg endpoint list
        lists all endpoint

Step 3: Apply an L3/L4 Policy
    Currently there are no policies in place, both clients are being accepted by the server.
    kubectl create -f https://raw.githubusercontent.com/cilium/cilium/1.17.0/examples/minikube/sw_l3_l4_policy.yaml
        In the premade file, CiliumNetworkPolicies match pod labels using an “endpointSelector” to identify the sources and destinations. 
        The above policy whitelists traffic sent from any pods with label (org=empire) to deathstar pods with label (org=empire, class=deathstar).
        This denies traffic from one client while allowing it for the other.

Step 4: Verfiy Policy Effect
    kubectl exec xwing -- curl -s -XPOST deathstar.default.svc.cluster.local/v1/request-landing
    kubectl exec tiefighter -- curl -s -XPOST deathstar.default.svc.cluster.local/v1/request-landing
        Xwing request will hang as it is now blocked, It doesn't have the right label and will be blocked by the server.
        Tiefighter request will go through, as it has the correct label and will not be blocked

Step 5: Inspect policies
    kubectl get cnp
    kubectl describe cnp rule1

        This will show all policies in Effect
        This will show the policy file in effect.

Step 6: L7 Policy
    kubectl apply -f https://raw.githubusercontent.com/cilium/cilium/1.17.0/examples/minikube/sw_l3_l4_l7_policy.yaml
        Currectly any client with the right label / class can make any call to the server api.
        This is not good, we only want them to make calls that we are expeting or are made for them.
        The L7 policy restricts what Https the client can reach. In this case they can only reach /v1/request-landing.

Step 7: Verify Policy
    kubectl describe ciliumnetworkpolicies
    kubectl exec tiefighter -- curl -s -XPOST deathstar.default.svc.cluster.local/v1/request-landing
    kubectl exec tiefighter -- curl -s -XPUT deathstar.default.svc.cluster.local/v1/exhaust-port
        We can see that our pod can only reach request landing and is denied access to exhaust port.

Step 8: Clean up
    kubectl delete -f https://raw.githubusercontent.com/cilium/cilium/1.17.0/examples/minikube/http-sw-app.yaml
    kubectl delete cnp rule1
        This just deletes everything.
